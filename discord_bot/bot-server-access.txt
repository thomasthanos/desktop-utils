2. ΤΙ ΠΗΓΕ ΣΤΡΑΒΑ
--------------------------------------------------------------------------------

  Έγινε format στα Windows. Το ιδιωτικό κλειδί SSH δεν ήταν αποθηκευμένο
  πουθενά αλλού, οπότε χάθηκε. Ο server δέχεται ΜΟΝΟ κλειδί (το
  PasswordAuthentication είναι κλειστό), άρα:

    - καμία σύνδεση SSH δεν ήταν δυνατή
    - το bot συνέχιζε να τρέχει κανονικά όλο αυτό το διάστημα

  Τρία λάθη που κόστισαν χρόνο, για να μην ξαναγίνουν:

    a) `ssh 38.45.65.119` χωρίς χρήστη
       Το SSH βάζει το όνομα χρήστη των Windows, δηλαδή `thomas@`. Ο server
       δεν έχει τέτοιον χρήστη. Πάντα:  ssh root@38.45.65.119

    b) Οι εντολές του Linux δόθηκαν στο cmd των Windows
       Το `mkdir -p /root/.ssh` στο cmd βγάζει "The syntax of the command is
       incorrect". Αυτές οι εντολές τρέχουν ΜΕΣΑ στην console του server.

    c) Μπερδεύτηκαν δύο διαφορετικοί κωδικοί
       VNC Password   = ανοίγει το ΠΑΡΑΘΥΡΟ της console (δεξιά στο panel)
       Change Password = ο root του UBUNTU        (αριστερά στο μενού)
       Το "Login incorrect" το έβγαζε το Ubuntu, όχι το VNC.

  Και η βασική αιτία του "Login incorrect": στα Ubuntu cloud images ο root
  ΔΕΝ έχει password — ο λογαριασμός είναι κλειδωμένος και μπαίνεις μόνο με
  κλειδί. Σε login από οθόνη, κάθε κωδικός απορρίπτεται, ακόμα κι ο σωστός.
  Πρέπει πρώτα να οριστεί κωδικός από το panel.

3. Η ΔΙΑΔΙΚΑΣΙΑ ΑΝΑΚΤΗΣΗΣ  (αν ξαναχαθεί το κλειδί)
--------------------------------------------------------------------------------

  ΒΗΜΑ 1 — Νέο ζευγάρι κλειδιών στα Windows

      ssh-keygen -t ed25519 -C "thomas-windows"

    Enter σε όλα. Δες το δημόσιο:

      type %USERPROFILE%\.ssh\id_ed25519.pub


  ΒΗΜΑ 2 — Ανέβασέ το στο GitHub (εδώ το paste δουλεύει)

      https://github.com/settings/ssh/new

    Title: thomas-windows,  Key: το περιεχόμενο του .pub,  Add SSH key.
    Αυτό είναι το κόλπο που γλιτώνει την πληκτρολόγηση 68 χαρακτήρων base64
    μέσα στο VNC, όπου ΔΕΝ δουλεύει το paste.


  ΒΗΜΑ 3 — Άνοιξε την console του server

      panel -> server305 -> Settings -> VNC
      Δεξιά: όρισε "VNC Password" (είναι ο κωδικός του παραθύρου)
      Πάτα "Launch VNC"


  ΒΗΜΑ 4 — Δώσε password στον root

      panel -> Settings -> αριστερά "Change Password"

    Χωρίς αυτό το login στην console αποτυγχάνει πάντα (βλ. ενότητα 2).
    Αν ζητήσει reboot, δεν πειράζει: το discord-bot.service έχει
    WantedBy=multi-user.target και Restart=always, σηκώνεται μόνο του.


  ΒΗΜΑ 5 — Μέσα στη VNC console, ως root

      ssh-import-id-gh thomasthanos

    Εναλλακτικά, αν λείπει το ssh-import-id:

      mkdir -p /root/.ssh && curl -s https://github.com/thomasthanos.keys >> /root/.ssh/authorized_keys && chmod 600 /root/.ssh/authorized_keys

    Ή, τελευταία λύση, γράφοντας το κλειδί στο χέρι:

      mkdir -p /root/.ssh && chmod 700 /root/.ssh && echo "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAILlTJQWATwZsPUcZOo+2JdneDFmVVBH5QnKZoB9yfuzb thomas-windows" >> /root/.ssh/authorized_keys && chmod 600 /root/.ssh/authorized_keys && echo OK


  ΒΗΜΑ 6 — Επαλήθευσε ΠΡΙΝ κλείσεις το VNC

      ssh-keygen -lf /root/.ssh/authorized_keys

    Πρέπει να δεις:  SHA256:NLXTJS8owNbuwMC4+cOrxFprJiLX3zXzS5YZkL2jbrg

    Το VNC μένει ανοιχτό μέχρι να επιβεβαιωθεί ότι μπαίνει το SSH. Είναι ο
    μόνος δρόμος πίσω αν κάτι πήγε στραβά.


  ΒΗΜΑ 7 — Από τα Windows

      ssh root@38.45.65.119

5. DEPLOY ΝΕΟΥ ΚΩΔΙΚΑ
--------------------------------------------------------------------------------

  Πρώτα push από τα Windows, μέσα στον φάκελο του project:

      git add -A && git commit -m "μήνυμα" && git push origin main

  Μετά, μία εντολή στον server:

      ssh root@38.45.65.119 "cd /opt/discord-bot && sudo -u discordbot git pull && sudo -u discordbot npm ci --omit=dev && sudo -u discordbot npm run smoke && systemctl restart discord-bot"

  Η σειρά έχει σημασία: το smoke τρέχει ΠΡΙΝ το restart. Με &&, αν κάτι
  σπάσει (π.χ. λάθος χτισμένο native module μετά το npm ci), η αλυσίδα κόβεται
  και το bot ΔΕΝ επανεκκινείται — συνεχίζει με τον παλιό κώδικα από τη μνήμη
  αντί να πέσει.

  ΠΡΟΣΟΧΗ όταν αλλάζει αρχείο μέσα στο deploy/ (systemd unit ή timer):
  τα units ΔΕΝ ζουν στο repo, τα αντιγράφει το setup.sh στο /etc/systemd/system.
  Σκέτο git pull δεν τα ενημερώνει. Τότε η εντολή θέλει και αυτά τα δύο:

      install -m 644 deploy/<το-unit> /etc/systemd/system/ && systemctl daemon-reload

6. ΧΡΗΣΙΜΑ ΣΤΟΝ SERVER
--------------------------------------------------------------------------------

  Κατάσταση bot            systemctl status discord-bot
  Logs ζωντανά             journalctl -u discord-bot -f
  Μόνο προβλήματα          journalctl -u discord-bot -p warning --since today
  Επανεκκίνηση             systemctl restart discord-bot
  Έλεγχος υγείας           npm --prefix /opt/discord-bot run smoke
  Χειροκίνητο backup       systemctl start discord-bot-backup.service
  Ποια μοντέλα AI παίζουν  cd /opt/discord-bot && sudo node src/tools/diag-ai.js
                           (θέλει root: το /etc/discord-bot.env είναι 600 root:root)
